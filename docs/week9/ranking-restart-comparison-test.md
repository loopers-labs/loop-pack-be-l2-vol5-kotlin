# 랭킹 재시작 비교 테스트

2026-11-19, 랭킹 스텝이 중간에 실패한 뒤 같은 파라미터로 재시작한 결과가 한 번에 끝난 결과와 같은지 확인했다. 테스트는 `WeeklyRankingRestartComparisonTest` 에 있고, 두 경우 모두 통과했다.

## 준비

- 청크 크기를 `ranking.chunk-size=2` 로 띄운다. 기본값은 100 이고, 이 테스트만 2 다.
- 2026-08-17 주 (`2026_08_3`) 에 구매 4 행을 넣는다. `requestDate` 는 2026-08-24 다.

| 주문 | 상품 | 수량 | 확정 (UTC)          |
| ---- | ---- | ---- | ------------------- |
| 42   | 7    | 3    | 2026-08-18 10:00:00 |
| 42   | 8    | 1    | 2026-08-18 10:00:00 |
| 43   | 9    | 5    | 2026-08-19 10:00:00 |
| 44   | 7    | 2    | 2026-08-20 10:00:00 |

## 기대값

| 상품 | 점수 | 순위 |
| ---- | ---- | ---- |
| 7    | 5    | 1    |
| 9    | 5    | 2    |
| 8    | 1    | 3    |

- 7 과 9 는 동점이라 상품 id 가 작은 7 이 앞이다.
- 입력 checksum 은 스냅샷 정보 행에 저장된 값이다. 사본 행을 `order_id`, `product_id` 순으로 `order_id`·`product_id`·`quantity`·`confirmed_at` 을 TAB 으로 잇고 행마다 LF 를 붙여 SHA-256 으로 만든다.
- 결과 checksum 은 랭킹 행을 순위 순으로 `productId`·`score`·`ranking` 을 TAB 으로 잇고 행마다 LF 를 붙여 SHA-256 으로 만든다. 저장하지 않고 테스트에서만 계산한다.

## 정상 실행

한 번에 `COMPLETED`. 점수·순위, 입력 checksum, 결과 checksum 이 모두 기대값과 같다.

## 재시작

상품 8 의 랭킹 INSERT 가 실패하도록 테스트에서 `product_ranking` 에 CHECK 제약 (`product_id <> 8`) 을 걸었다. 순위 순서가 7, 9, 8 이라 첫 청크 (7, 9) 는 커밋되고 두 번째 청크 (8) 에서 실패한다.

| 단계                   | 결과                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------- |
| 첫 실행                | `FAILED`, 랭킹 2 행 (7, 9), 저장된 리더 위치 2, 포인터는 `PUBLISHED` 가 아님           |
| 제약을 풀고 같은 파라미터로 재실행 | 같은 JobInstance, 새 JobExecution, `COMPLETED`                                |
| 재실행 뒤              | 점수·순위, 입력 checksum, 결과 checksum 이 정상 실행과 같은 기대값, 포인터 `PUBLISHED` |

## 기획 문서와 다른 점

- 기획 문서는 상품 9 에서 실패시켜 7·8 을 남긴다. 상품 id 순서를 가정한 것이고, 실제 순위 순서는 7, 9, 8 이라 상품 8 에서 실패시켜 7·9 를 남겼다.
- 기획 문서는 비교용 정상 실행을 다른 주에서 따로 돌린다. 다른 주면 주문 id 와 확정 시각이 달라 입력 checksum 이 같을 수 없어서, 정상 실행과 재시작을 같은 fixture 로 각각 돌려 같은 기대값과 비교했다.
- 실패 스위치는 운영 코드에 두지 않고 테스트의 CHECK 제약으로 만들었다.

## 이 테스트가 보지 않는 것

재시작 사이에 입력이 바뀌는 경우 (r2 가 생기는 경우) 는 보지 않는다. 그 경우는 `ranking-r1-r2-test.md` 의 T1a·T1b 이고 아직 실패한다.
